## Page / interaction

Admin-only Reports tab in Faculty Dashboard, using its shared shell, tokens, buttons and table styles. Code/CSS load only when the tab opens. Faculty/HICC/VISC/office roles have no entry and receive403 from the API regardless of UI.

Top toolbar: academic year, data-source checkboxes, Preview. Each selected source has collapsible Columns (select all/clear, move up/down) and Filters. Conditions select a catalog field, its valid operator, and typed value(s); Match all/Match any implements AND/OR per source, up to20 conditions. Source selection and output columns are distinct: a permitted filter field need not be exported. Preview is explicit; changing a definition invalidates the previous preview/export rather than silently reusing stale results.

Results have one tab/table per selected source, total and per-table counts,50-row server pages, selected column order, sort field/direction, Copy this page, Download CSV (current table), Download Excel (all selected tables), generated-at time and source coverage. Empty results retain headers; loading and errors expose Retry. Search text matches independent words, including canonical surname/given-name order. Narrow screens wrap controls and scroll tables horizontally; keyboard controls remain native buttons/inputs. Internal IDs are not normal report columns.

## Sources / grain / permitted output

1. **Faculty annual workload** — one row per active roster faculty in the selected year. Selectable fields: canonical faculty name, rank, stream, FTE, teaching-session count, CCC/Rotation/other-work record counts, appointment count, contract/effective teaching target, scheduled-teaching DOE, role DOE, raw/applied supervision DOE, adjustments, assigned teaching DOE, remaining DOE, recorded teaching/role/total DOE, effective recorded DOE, calculation basis, status, policy reference, source reference and academic year. Authoritative Worksheet and Dashboard values remain distinct. Null stays unavailable, never0. Counts use canonical FacultyId links and distinct source IDs; never match people by display name. Unmapped work records are disclosed as source coverage, not assigned by guesswork. No new DOE calculation or publication occurs.
2. **Teaching / work details** — one row per teaching session or original work range, not a cross-product of instructors and appointments. Fields: source kind, faculty list, curriculum year, course/code/name, type, topic/activity, start/end dates, displayed time, time evidence/status, room and academic year. Work includes CCC, Rotation and other existing work categories; excludes Remote work/AFC. Locum remains literal. Source ranges include weekends and remain unexpanded. Missing work time displays08:30–16:30 with Default time/Needs Review; actual source evidence remains available and is never rewritten or credited. Teaching missing time remains truthful. This first version does not calculate hours or DOE from defaults.
3. **Appointments / roles** — one row per recorded validity period, retaining unknown/open endpoints and period gaps. Fields: faculty, role/category, course/area/rotation, course name, details, start/end, appointment reference, period number, whole-appointment recorded/override/effective DOE, DOE basis/status and academic year. Whole-appointment DOE is explicitly non-additive across repeated periods; no generic SUM is offered. Existing role projection/calculation values are reused, not recalculated or source-overwritten.
4. **Change history** — independent recorded audit source, one row per authorized field change within the selected business academic year: time UTC, operation, domain/type, faculty, course/session, field, From/To, start/end and By whom. Reuse the existing History API projection and coverage limits; no past-state reconstruction, raw metadata/UUIDs, or fabricated pre-audit records. Raw From/To evidence stays unchanged; only surrounding person-name labels use the shared formatter.

No direct AFC purpose/PDF, UCID, email, confidential personnel notes or raw audit metadata are in this v1 field registry. Their existing workflows and access rules remain unchanged. Dataset-specific source coverage is explicit; an active roster summary is not a promise that every historical schedule record belongs to an active faculty.

## Query and snapshot contract

Server registry is the authority for dataset/field IDs, data types, permitted operators, labels, units, defaults, source/grain and provenance. Browser receives its authorized catalog. Query uses only registered fields and parameterized existing source readers, never raw SQL or caller-selected identifiers.

`POST /api/v1/reports/query` accepts canonical academicYear and1–4 dataset definitions `{source,columns,match,filters,sort}`. Unknown/duplicate keys, fields, sources, columns, invalid operators/values,20+ conditions, malformed academic years, excessive payloads or zero columns fail400 before source reads. Number/date/boolean operators are typed; blank uses explicit isEmpty/isNotEmpty, and missing values do not become numeric0. Predicates execute on permitted normalized fields before output-column projection. Max32 columns/source,5000 rows/source,10000 rows total,200000 selected cells and6MiB snapshot; exceeding any bound returns413 with a narrow-filters message, never a truncated success. Source failures return503 and create no partial snapshot.

Current Firebase token + active SQL profile is required before any read. Use existing canonical administrator-role helpers (including legacy compatibility). Existing support-mode routing already denies the new reports path; preserve that restriction and do not expand its allowlist. Snapshot binding covers UID/normalized role; no support-context report request reaches the API. Recheck authorization after asynchronous source loading and after file rendering. Profile/role change discards that actor's previous private snapshots.

Opaque UUID snapshots bind UID, normalized role, support context and academic year/definition; lifetime10minutes, at most2 per actor/8 globally, and capped total memory. One query per actor/two globally; one export globally. GET catalog/page/export are no-store. Page requests select only a table already in the snapshot and offsets in50-row increments. CSV selects one included table; XLSX all included tables. Both serialize exactly the snapshot's selected columns/rows/order. Source read windows are captured and displayed; a multi-source preview is not a claim of a serializable database transaction. History-derived expiry may shorten preview lifetime to its original snapshot expiry. Reset/query edits/logout/tab leave clear private rendered results and disable exports; stale responses cannot repopulate another identity or query.

Export uses existing ExcelJS dependency lazily, safe CSV quoting/BOM, formula-prefix protection including hidden whitespace/control characters, cell-length and6MiB file limits. Names use server domain/person-name and frontend faculty-name modules at presentation boundaries; no identity/source field mutation. CSV/Excel contain no excluded columns or raw source objects. Browser validates artifact shape/size before download, following existing History transport patterns.
